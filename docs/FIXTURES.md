# Fixtures

**DEV ONLY.** Never run against production.

```bash
make fixtures
```

## What it creates

1. **DEV admin user** (credentials auth)
   - Email: `DEV_ADMIN_EMAIL` (default `admin@quizlink.local`)
   - Password: `DEV_ADMIN_PASSWORD` from **gitignored** `.env.docker` (generated by `make install`)
   - Name: `DEV_ADMIN_NAME`
   - `role = ADMIN`
   - `emailVerifiedAt` set (can sign in immediately)
   - `passwordHash` via bcrypt (same path as real email/password signup)
2. **Default coin packs** (`STARTER`, `BOOST`, `PRO`) if missing

No fake Google accounts. No production emails. No password is committed to the repository.

## Idempotency

Safe to run twice:

```bash
make fixtures
make fixtures
```

- Admin is upserted by email (one row)
- Coin packs are skipped when the unique `name` already exists

## Configuration

`make install` writes a strong `DEV_ADMIN_PASSWORD` into `.env.docker` when missing or still `change-me`.

```env
DEV_ADMIN_EMAIL=admin@quizlink.local
DEV_ADMIN_PASSWORD=<generated locally — never commit>
DEV_ADMIN_NAME=QuizLink Dev Admin
```

Placeholders such as `change-me` are **rejected** by fixtures until replaced/generated.

## Safety guards

Fixtures refuse to run when:

- `NODE_ENV=production` (no override)
- `ALLOW_DEV_FIXTURES` is not `1` (`make fixtures` sets this)
- `DATABASE_URL` host is not `db`, `localhost`, or `127.0.0.1`
- `DEV_ADMIN_PASSWORD` is missing or a placeholder

Example (must fail immediately):

```bash
NODE_ENV=production make fixtures
NODE_ENV=production make fixtures-reset
```

## Implementation

- Script: `scripts/dev/seed-fixtures.ts`
- Package script: `pnpm fixtures` (still requires the guards above)

Related tools (not used by `make fixtures`):

- `pnpm promote:admin` — promote an **existing** user
- `pnpm seed:dev-users` — bulk demo users for admin charts
- `pnpm seed:coin-packs` — coin packs only

## Fixtures vs migrations

| | Migrations | Fixtures |
|--|------------|----------|
| Purpose | Schema | Sample / bootstrap data |
| Command | `make migrate` | `make fixtures` |
| Production | yes (`migrate deploy`) | **never** |

## Destructive reset (DEV ONLY)

```bash
make fixtures-reset
```

**Warning:** deletes the DEV admin row (`DEV_ADMIN_EMAIL`), then recreates fixtures.
Requires typing `YES`. Refuses when `NODE_ENV=production` **before** any confirmation or DB access.
Does **not** wipe the whole database.

Full wipe (DEV ONLY):

```bash
docker compose --env-file .env.docker down -v
make install
make start
make fixtures
```

## Extending fixtures

Edit `scripts/dev/seed-fixtures.ts`, keep operations idempotent, update this doc, and add Vitest coverage for non-trivial helpers.
